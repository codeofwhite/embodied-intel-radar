# 统计、排序与证据边界

## 数据流

公开来源 → 标准化岗位 → SQLite 与逐次观测 → 报告/网站 JSON → 私有 Worker + D1 → 前端。个人收件箱独立于招聘数据库，不参与岗位计数。

## 证据层级

公司官方页面、招聘平台/高校转载、搜索线索、个人保存需要分别标注。解析成功只说明采集时取得内容；是否仍开放必须回到原页面核验。未解析详情的入口不应计为完整岗位。

## 统计

岗位数同时呈现独立公司数。薪资只统计明确披露的全职月薪，不把实习日薪换算为全职薪资。单次快照只描述横截面；跨日期差异可能来自解析或来源变化，不能直接等同企业扩招。

## 个人匹配

collector/config.json 中 profile_signals 是用户设置的技能信号。覆盖率比较配置技能与岗位信号，并不认证技能熟练度。公开版使用演示列表；job_priority 的企业名称加分列表为空，其他规则仍可配置。

## 入门压力代理

代码 pressure_proxy：55% × 非入门岗位占比 + 25% × 硕博门槛占比 + 20% × 岗位集中度。该启发式不包含真实投递人数，可信度低，不应称为真实竞争强度。岗位优先分也不是录用概率。

## 内容生成

职责与要求由岗位文本提取；模拟面试问题是准备建议，不是公司原题。社媒索引与个人保存均为待核实线索。行情独立于就业统计，非投资判断。
